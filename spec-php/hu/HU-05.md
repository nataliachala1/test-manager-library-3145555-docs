# HU-05 · Gestionar socios

## Identificación y objetivo original
HU-05 · Gestionar socios. Actores Administrador y Bibliotecario. Registrar socios y localizar sus datos.

## Descripción y criterios originales
Admin y bibliotecario crean socios con nombre/documento. Se listan y buscan por nombre/documento; no se eliminan.

- **CA-05.1** El admin y el bibliotecario crean socios con nombre y documento. El documento es único: repetido 409.
- **CA-05.2** Se lista y se busca por nombre o documento, paginado.
- **CA-05.3** Los socios no se eliminan.

## Reglas, contrato y datos
document_number es único; no hay borrado. Entrada full_name/document_number; listado q/page/size; detalle incluye active_loans. Salida socio o lista paginada. Endpoints GET /api/v1/members, GET /api/v1/members/{id}, POST /api/v1/members. Entidad member (id, full_name, document_number).

## Dependencias, tareas, pruebas y aceptación
Depende de HU-01; HU-06 y HU-08 relacionan socio con préstamos. Responsables: api (caso de uso/consulta/persistencia), app (gestión/consulta). Tareas T-06, T-12, T-16, T-22; trazabilidad antes implícita queda explícita.
- CA-05.1: ambos roles crean; documento repetido da 409.
- CA-05.2: búsqueda por nombre/documento y listado paginado.
- CA-05.3: no hay endpoint de borrado y socio de préstamos permanece.
Evidencia de caso de uso, unicidad, roles, búsqueda/paginación y persistencia.
