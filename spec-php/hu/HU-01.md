# HU-01 · Iniciar sesión

## Identificación y objetivo original
HU-01 · Iniciar sesión. «Como usuario quiero autenticarme para operar según mi rol.» Actores: usuario registrado admin o librarian.

## Descripción y criterios originales
Credenciales válidas dan token Bearer por ocho horas; rutas protegidas exigen token y autorizan por rol.

- **CA-01.1** Con credenciales válidas se recibe un token con vigencia de 8 horas.
- **CA-01.2** Con credenciales inválidas responde 401 con un mensaje que **no** dice si falló el usuario o la clave.
- **CA-01.3** Todo endpoint salvo el inicio de sesión y `/health` exige token. Sin token: 401. Rol insuficiente: 403.

## Reglas, contrato y datos
RN-6; JWT HS256 de ocho horas con sub y role; clave como hash, nunca devuelta ni registrada. Entrada username/password; salida access_token, token_type, expires_in, role. Endpoints POST /api/v1/auth/login y GET /api/v1/health. Entidad user (id, username, password_hash, role). Paquete JWT pendiente DT-001; código para token ausente/inválido/vencido pendiente DT-012.

## Dependencias, tareas, pruebas y aceptación
No depende de otra HU; es precondición de rutas protegidas. Responsables: api (autenticación/autorización), app (inicio de sesión); infra (motor). Tareas T-07, T-14, T-16, T-17; DT-001, DT-009.
- CA-01.1: token con vigencia de 28 800 segundos.
- CA-01.2: credenciales inválidas dan 401 sin distinguir cuál falló.
- CA-01.3: protegida sin token da 401; rol insuficiente, 403; login y salud públicos.
Evidencia HTTP y revisión de que clave/hash no aparezcan en respuestas ni logs (RNF-3). Cierre de respuesta 401 depende de DT-009 y DT-012.
